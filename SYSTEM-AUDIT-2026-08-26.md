## Credential Delivery Recovery Control
- Added a dedicated 10-second credential_resend_watch independent of the normal recruit accession watcher.
- The recovery watcher works for Replacement and already-enlisted Soldiers and does not alter personnel assignment or recruit roles.
- Resend uses the current pending plaintext credential when available; Field Code rotation occurs only after explicit Command authorization on the Website.
- Successful/failed delivery is reported to the Website, where a permanent credential-delivery event is recorded.

- 2026-08-26: Approved recruits now receive both Replacement Depot and 5th Cavalry Regiment immediately on approval. Canonical personnel sync preserves 5th Cavalry Regiment through onboarding and removes only Replacement Depot after permanent assignment.

## Nightly seeding automation — 2026-08-26
- Added persistent `/set-seeding-channel`, `/seeding-status`, and `/clear-seeding-channel` commands.
- Added Eastern-time seeding slots at 20:00, 20:30, 21:00, and 21:30 America/New_York.
- Seeding messages only send with current HLL RCON telemetry and population below 40; 40+ suppresses the slot.
- Sent slots are persisted in `clerk_seeding_notices` so restarts do not duplicate alerts.
- No @everyone/@here mention is generated by the automation.
- This change advertises Seeding Ribbon/Medal credit in the requested Discord copy; it does not create a new award-credit calculation system by itself.

## Seeding populated-state / regiment role mention — 2026-08-27
- Discord seeding worker now uses the same configurable `HLL_SEED_READY_PLAYERS` threshold as HLL telemetry (default 40).
- No seeding Discord message is sent once the live server population is at/above that threshold.
- Low-population seeding calls mention the `5th Cavalry Regiment` Discord role, with @everyone/user pings disabled.
