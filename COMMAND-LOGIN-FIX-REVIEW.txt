5TH CAVALRY — COMMAND LOGIN / S-1 REPLACEMENT FIX

Root cause:
The S-1 personnel exception scan queried personnel_appointments.status='ACTIVE'.
The personnel_appointments table has no `status` column; the authoritative fields are
`is_current` and `appointment_status`. This caused Command/S-1 Action Center login to fail.

Correction:
- Leadership exception scan now uses is_current=TRUE AND ended_date IS NULL.
- Replacement Detachment and personnel-exception summary widgets are fail-soft so a
  non-critical analytics error can never block the entire Command Action Center.
- Existing Replacement Detachment workflow, S-3 operation deletion, homepage schedule,
  unified website scheduling, and M16 functionality are retained.
